    Comparatif des différentes technologies

    Tableau Avantages / inconvénients technologies :

    Avantages Inconvénients
    Cross Platform
    • Une seule équipe et une base de code unique = moins de dépenses de moitié par rapport à deux développements séparés.
    • Le lancement sur le marché est plus rapide grâce à la mutualisation des efforts de développement.
    • Les mises à jour et la correction des bugs s'appliquent en même temps à toutes les versions
    • L'utilisation d'une couche intermédiaire ou d'un moteur partagé peut ralentir l'application face au code natif.
    • L'intégration de fonctionnalités très spécifiques liées au téléphone s'avère parfois complexe.
    • Le rendu visuel peut s'éloigner légèrement des codes ergonomiques propres à chaque système (iOS ou Android).
    Appli Web
    • L'appli accessible depuis n'importe quel appareil via un navigateur web.
    • Pas besoin de télécharger un fichier lourd ou de passer par un App Store
    • Les modifications sont déployées directement sur le serveur la dernière version (direct)
    • Un seul code source fonctionne sur tous les systèmes d'exploitation → réduit les coûts initiaux par rapport à des appli natives.
    • L'application nécessite le plus souvent une connexion Internet active
    • Généralement moins rapides et moins puissantes que les applications natives
    • L'accès aux fonctionnalités avancées de l'appareil est plus restreint via un navigateur.
    • Contrairement aux stores d'applications, une application web dépend de la visibilité sur les moteurs de recherche.
    Appli mobile
    • L'application utilise les fonctionnalités du téléphone (appareil photo, GPS…)
    • Une partie des données reste accessible hors connexion internet.
    • Les applications natives s'exécutent plus rapidement et plus fluidement.
    • Le développement et la maintenance demandent un budget important
    • La publication sur l'App Store ou Google Play impose des règles strictes, des frais de licence annuels…
    • Les évolutions des systèmes d'exploitation exigent une maintenance technique continue.
    Logiciel Bureau
    • Le programme tourne sans ralentissement lié au réseau, elle fonctionne sans connexion Internet.
    • Les données restent stockées sur la machine de l'utilisateur, ce qui protège la confidentialité.
    • Le logiciel accède facilement aux périphériques de l'ordinateur (imprimantes, clés USB…).
    • Chaque poste doit recevoir les nouvelles versions manuellement ou via un système automatisé.
    • Il faut souvent réécrire ou adapter le code pour Windows, macOS et Linux.
    • Le partage du logiciel est plus lourd que l'envoi d'un simple lien vers un site Web.
    Progressive Web App
    • L'accès aux fonctionnalités poussées du téléphone (Bluetooth…) reste restreint comparé à une application native.
    • Absence d'une présence native sur les boutiques d'applications classiques limite la découverte spontanée par de nouveaux utilisateurs.
    • Certaines fonctionnalités des PWA restent moins bien prises en charge sur Safari comparé à l'écosystème Android.
    • Une mauvaise gestion du cache ou des scripts en arrière-plan peut parfois consommer davantage d'énergie.
    • Coût et temps de développement réduits
    • L'installation se fait directement depuis le navigateur sur l'écran d'accueil, ce qui évite de passer par un tier (App Store …)
    • Grâce aux services workers, la PWA peut charger du contenu même sans connexion Internet ou sur un réseau de faible qualité.
    • L'application se met à jour en arrière-plan à chaque visite, sans action requise de la part de l'utilisateur.
    • Les PWA occupent très peu d'espace de stockage sur l'appareil par rapport à une application native.

    Tableau comparatif pour le projet

    Critères & Cas d'usage Progressive Web App (PWA) Application Cross-Plateforme
    Préparation sur PC (web) Excellente : L'application est nativement un site web. L'interface s'adapte parfaitement aux grands écrans (tableaux de bord, cartes interactives). Moyenne : Bien que Flutter ou React Native compilent pour le Web, le rendu "bureau" peut parfois sembler lourd ou moins naturel qu'une vraie page web.
    Utilisation Mobile (Consultation/Édition) Très bonne : Installation directe depuis le navigateur sans passer par les stores. L'UI est responsive. Excellente : Expérience 100% native avec des animations fluides et les composants d'interface standards d'iOS et Android.
    Mode Hors Ligne (OffLine) Bonne : Utilisation des Service Workers et de IndexedDB pour mettre en cache l'itinéraire et les données. Excellente : Accès direct au stockage natif de l'appareil (ex: SQLite) offrant une gestion de cache plus robuste pour les grosses bases de données.
    Intégration Spotify Limitée mais fonctionnelle : Utilisation des URI Web ou des liens profonds (ex: spotify://) pour ouvrir l'application. Optimale : Possibilité d'utiliser des SDK natifs Spotify pour un contrôle plus poussé (lecture directe dans l'app, authentification native).
    Cycle de développement (Agile) Très rapide : Une seule base de code (Web). Mises à jour instantanées sans validation par les App Stores (Apple/Google). Plus complexe : Nécessite de compiler pour les stores. Les cycles de validation Apple/Google peuvent freiner les itérations agiles.

    Résumé

    La PWA transforme un site web en une application dluide, installable et résiliente aux problèmes de connectivité.
